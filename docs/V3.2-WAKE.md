# v3.2 唤醒：成员上报后叫醒主会话

## 1. 机制

成员调用 `ms2_report` 后，处理顺序是：

1. `Coordinator.report` 校验参数、消歧工单、写 `report` 账本记录；
2. 落账成功后更新内存里的任务状态（completed + provisional / needs_human / failed）；
3. 调用注入的 `onReported(task)`；
4. `plugin2.mjs` 里的 `createWaker` 用 `sessionController.prompt` 向该整体 lead 投一条 `mode: 'followup'` 的消息。

唤醒文本固定为：

```text
[成员上报] <成员label> · <taskRequestId> · <state>：<summary 截断 200 字>（详情：调用 ms2_status）
```

`summary` 先经过 `cleanWakeSummary`：去掉 `\u0000-\u001f\u007f` 控制字符、折叠空白、trim；再按 Unicode 码点截到 200 字。`label` 为空时用「未命名成员」。

## 2. 为什么不会打断主会话

`sessionController.prompt` 的 `mode: 'followup'` 走的是 agent 的排队通道：

- lead 空闲时，这会开一个新回合；
- lead 忙碌时，消息进入收件箱排队，不打断当前回合。

插件没有新增定时器，也没有改客户端轮询频率；唤醒只在 `ms2_report` 的处理路径里触发。

## 3. 幂等

唤醒的 requestId 是：

```text
ms-wake-<taskRequestId>-<status>
```

`createWaker` 在进程内维护 `sent` 集合，先登记再投递。同一张工单、同一个状态重复上报（包括模型重试）只会产生一次 prompt。不同状态（例如先 blocked、后 failed）各自有独立幂等键。

重复上报本身由 `reportKey` 短路为 `duplicate`，不会再次走到唤醒。

## 4. 自唤醒防护

如果 `leadSessionId === reporterSessionId`，`createWaker` 直接返回 `{ status: 'skipped-self' }`，不调用 `prompt`。Coordinator 也会先判一次，避免无意义的注入调用。

在 `ms2_report` 的返回 data 里能看到 `wake` 字段（`sent` / `duplicate` / `skipped-self` / `skipped-no-lead` / `error`）。

## 5. 失败隔离

唤醒失败按三类处理：

- `prompt` 同步抛错：`wake` 捕获；
- `prompt` 返回 rejected Promise：挂 `.catch` 记录；
- `sessionController` 缺失或没有 `prompt`：记录 `NO_SESSION_CONTROLLER`。

错误只进入 waker 的 `wakeErrors`（最多 20 条），字段为：

```json
{"at":"...","groupId":"g-...","taskRequestId":"ms-...","requestId":"ms-wake-...","code":null,"message":"..."}
```

`ms2_report` 仍然返回成功，账本不受影响。`ms2_status` 的 data 里有 `wakeErrors`，按调用者可见整体过滤。

## 6. 权限边界

唤醒不走工具通道，也不经过插件 guard：它是 `ms2_report` 成功后的内部动作，不是成员获得的新工具，因此不需要、也没有放宽 `guard`。成员仍然只能调 `ms2_report`，不能借此调用 `send_message`、`ms2_dispatch` 等。

## 7. 已知边界

- 唤醒会消耗 lead 一个模型回合；lead 空闲时立即触发，忙碌时排队。
- 同一工单同一状态只投一次；如果第一次投递失败，不会自动重试（避免刷屏），错误留在 `wakeErrors` 里供排查。
- `sent` 集合是进程内状态；宿主重启后，同一工单再次上报会重新触发一次唤醒。这是有意为之：重启后无法可靠知道上一次 prompt 是否已送达。
- 唤醒文本只带 summary 前 200 字；完整 detail 仍在账本里，通过 `ms2_status` 查看。
- 本功能未改 README、未改版本号；版本仍为 1.2.0。

## 8. 测试

`tests/wake.test.mjs` 5 条：

1. completed 上报后恰好一次 prompt，sessionId 是 lead，requestId 为 `ms-wake-<id>-completed`，文本含成员 label 与 taskRequestId；
2. 同一单重复上报仍只有一次唤醒；
3. 上报者就是 lead 时不调用 prompt；
4. prompt 抛错时 `ms2_report` 仍成功，`wakeErrors` 记录一条；
5. 超长/带控制字符的 summary 被截到 200 字且无控制字符。

全套 `node --test tests/*.test.mjs`：167 tests / 167 pass。
