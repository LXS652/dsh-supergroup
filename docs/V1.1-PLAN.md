# v1.1 实施方案：让 dsh-supergroup 在「设置 → 插件列表」读成「超级代理部署」

> 这是 v1.1 的设计与交接记录，供后续维护者参考，非安装文档。

> 状态：设计代理人方案（未执行）。所有结论基于只读核实：宿主 asar 源码逐行、profile 实况、两个仓库文件。
> 复核基线：本机 DSH `0.2.2-rc.1`，profile `desktop`，node 24.21.0 / pnpm 11.28.5。
> 本文不含任何 token、密码或账号凭据。
> 本版相对上一版的**重心变更**：用户所指的「已安装插件列表」确认是**设置 → 插件列表**（Loader 投影），不是侧栏「插件」页。因此根因不是「没被 profile 选中」，而是**这条 entry 拿不到 `meta`，标题退化成一整条 `file://` 路径**。

---

## 0. 结论（TL;DR）

1. 设置 → 插件列表 = 纯 Loader 投影。每个非 group 条目一行，标题取 `meta.title`，取不到就退化成模块短名。**手写 insert 的条目本来就在列表里**，只是标题是一整条 `file:///<你的工作区>/dsh_multisession_stage23/src/plugin2.mjs`，副标题才是 `dsh-big-fat-fish`——用户认不出来，所以说「没显示」。
2. 这不是策略限制，是 `readPluginMeta` 第一行的硬编码：`barePackageName(specifier)` 对任何 `includes(":")` 的 specifier（`file:`、`http:`、`E:\`）直接返回 `undefined` → `meta` 恒缺失。**所以「手写 insert 永远拿不到 meta.title」成立**。唯一例外是把 `name` 写成裸包名，而裸包名必须能被 profile 的 `node_modules` 解析——那已经等价于「装成包」。→ **包化是拿到可读标题的必要条件。**
3. 但包化只解决「能拿到 meta」，不解决「标题是中文字」。标题回退链是 `locale.*.meta.title` → `manifest.name` → specifier，**`displayName` 根本没被读**。包安装但不带 locale 时，标题会显示 `supergroup`（`dsh-` 前缀被 `moduleShortName` 剥掉）。
4. 要读成「超级代理部署 / dsh-supergroup」，最小改动集只有 4 处（第 4 节）：`exports` 暴露 `./package.json` 与 `./locale/*.json`、新增 `locale/en.json` + `locale/zh.json`、`files` 加 `locale`、可选 `icon`。
5. 上一版说的「不改数据、不复制也能成功」**是错的**（修正见 C8）：装成包后 `import.meta.url` 推出的 `../data` 是 `<你的工作区>\dsh-supergroup\data`（发布仓里不存在），legacy 回退救不了迁移。**冷拷贝是必做步骤**，legacy 回退只当防止写进 `node_modules` 的安全网。
6. 实施顺序：改发布仓（它同时是安装源）→ 测试 → 退 DSH → 冷拷贝 → `dsh plugin add` → 删手写 insert → 启动 → 三处验收 → 才 push/tag。

## 1. 三个「列表」分别认什么（修正版）

| 入口 | 实现 | 数据来源 | 手写 insert 会显示吗 |
| --- | --- | --- | --- |
| **设置 → 插件列表**（用户所指） | `dsh-client-ui-settings-plugin-inventory`（UI）+ `dsh-host-plugin-inventory`（host） | `ctx.loader.entries()` 逐条投影；`meta` 来自可选服务 `pluginPackages` | **会**，但标题 = 整条 `file://` 路径，副标题 = entry id |
| 侧栏「插件」页 | `dsh-client-ui-plugin-manager` + `dsh-plugin-manager` | profile `dependencies` + `dsh.profile.bundles` + 包声明 `dsh.bundle.patch` | 不会（三者全不满足） |
| dshmarket | `dshmarket` | 扫 profile `node_modules` + bundles + `ownsLoaderEntry` | 不会（node_modules 里没有这个包） |

包化安装后，三处会同时变好：设置页有友好标题、侧栏插件页出现「组合包」卡片、dshmarket 也能认出（entry name = 包名）。

**当前实例其实已经在跑**：本会话工具表里的 `ms2_dispatch / ms2_group / ms2_status` 就是手写 insert 那条 entry 注册的 → entry 存在于 Loader → 设置页**必然**有它那一行。用户看不到的是「可读的名字」，不是「这一行」。

## 3. 判定：两个分支怎么区分

**分支 ①（高置信，已被间接证实）**：卡片在，标题是一长串 `file:///E:/…/plugin2.mjs`。
证据：本会话的 `ms2_*` 工具就是那条 entry 注册的 → entry 在 Loader → 列表必有此行。

**分支 ②**：真的没有这一行。那说明 entry 没进 Loader 树，排查顺序：
1. profile `cordis.patch.yml` 第 638–648 行 insert 是否还在（历史上被 `sanitizeProfile()` 改名成 `.bak-<ts>` 两次）；比对 `Get-FileHash` 与备份 `<你的工作区>\dsh-supergroup-backup-20261106-2111-cordis.patch.yml`。
2. `%DSH_HOME%\logs\startup-*.log` 有没有 patch 解析/加载失败。
3. 有没有 `duplicate loader entry id`（双 insert）。
4. `plugin-inventory` 这一行本身是否被 profile patch 禁用（搜 `plugin-inventory`）。
5. `file:///<你的工作区>/...` 的中文与 URL 编码：Windows 上合法，但 patch 里若写成反斜杠/未编码空格则模块解析失败（失败也会显示成 `failed` 行，而不是消失）。

**一次肉眼确认（用户，1 分钟，不用等实施）**：设置 → 插件列表 → 搜索框输入 `file://`，或 `big-fat-fish`。
- 有卡片、标题是长路径 → 分支 ①，本方案照做即可。
- 完全没有 → 分支 ②，先按上面 5 步查，再决定改法。

## 4. 达成可读标题的最小改动集（M1–M4）

> 只动发布仓 `<你的工作区>\dsh-supergroup`（它同时是安装源，也是唯一有 git 的仓）。

**M1 `package.json` 的 `exports` 增加两项**（少一项就静默退化，不报错）：
```json
"exports": {
  ".": "./src/plugin2.mjs",
  "./client": "./client/client.js",
  "./package.json": "./package.json",
  "./locale/*.json": "./locale/*.json"
}
```
- `./package.json`：`readPluginMeta` 第 3007 行只在 `packageName === specifier` 时读 manifest，且必须能被 Node 解析到。不给 → manifest 读不到 → 标题只剩 `specifier`。
- `./locale/*.json`：第 3005 行按 `${specifier}/locale/en.json` 解析。不给 → 词典为空 → 标题退成 `manifest.name`（即 `supergroup`）。

**M2 新增 `locale/en.json` 与 `locale/zh.json`**，格式与已装插件一致（实读多个已装插件均如此）：
```json
{ "meta": { "title": "Supergroup", "description": "Multi-session supervision: dispatch by session, ledger-backed reconciliation, preset rosters." } }
```
```json
{ "meta": { "title": "超级代理部署", "description": "多会话编排：按会话派单、账本回收结果、重启自动对账。" } }
```
- `en.json` 必须存在（它是 `dictionariesOf` 的入口，第 3005 行按它定位目录；没有它，`zh.json` 也不会被读）。
- 想更醒目可以写成 `"超级代理部署 (dsh-supergroup)"`——`dsh-context`、`dsh-dream-skin` 就是这么做的，但副标题已经会显示 entry id，建议保持干净。

**M3 `files` 增加 `"locale"`**：不加的话 `pnpm pack`/npm 安装后的包里没有 locale 文件，`file:` 安装能读到（目录原地），但 1.1.1 换 tgz 就会退化。

**M4（可选）icon**：`"icon": "./icon.svg"`（相对路径、必须在包目录内、≤256 KiB、svg/png/jpg/jpeg/webp）。给了以后 manifest 读得到就直接内联成 data URL；不给则退回尝试导出 `${specifier}/icon`（我们没有，就无图标）。**注意**：icon 出问题不会让卡片消失，只会在 meta 里带 `error` 字段。

**验收命令（不用起 GUI，先在命令行验证导出面）**——在 profile 目录下用宿主自带 node：
```powershell
$node='<你的 DSH_HOME>\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
& $node -e "console.log(require.resolve('dsh-supergroup/package.json'))"
& $node --input-type=module -e "const m=await import('dsh-supergroup/locale/zh.json',{with:{type:'json'}});console.log(m.default.meta.title)"
```
两条都要成功；第二条要打印 `超级代理部署`。

## 5. 对交接文档第 9 节草案的其余修正

### C1（必须）客户端模块 id 必须等于**包名**
`client/client.js:11` 现在写死 `id: 'dsh-big-fat-fish'`。`dsh-client-modules/README.zh.md` 第 82 行：「解析出的 manifest 包名作为浏览器模块身份」；`dsh-meme/client.js` 头注释：「注册 id 必须等于 loader entry 名」。包名是 `dsh-supergroup` → id 不改就是面板白屏 / 启动审计报错。`PANEL_ID='big-fat-fish'` 与侧栏 label「超级代理部署」**不动**。

### C2（必须）包自带 patch 的占位符 config 必须删干净
发布仓 `cordis.patch.yml` 现在是三个 `<你的 DSH_HOME>/data/*` 占位符。它们在任何机器上都是错路径（相对解析到 `node_modules/dsh-supergroup/` 下，甚至写出字面量目录）。包 patch 必须**零 config**，路径由代码解析。
副作用要知情：删掉 insert 会连带删掉 `bootstrapGroups`（整体 B）的种子，但 `groups.json` 已是权威，不影响；验收要确认「整体 B」还在。

### C3（必须）默认数据目录要带 legacy 回退，但**它救不了包安装**
`DSH_HOME` 可能是空串 → 空串视为未设置，退 `homedir()+'.dsh'`（`dsh-meme` 同款做法，注释写明「Windows 无 HOME」）。
`DEFAULT_REPORT_DIR`（`src/plugin2.mjs:972` selfTest）现在指包内 `probe2/`，装成包会写进 `node_modules`，必须跟着数据目录走。

### C4（修正）身份规则不是「包名 = insert id」
真实的认身份规则（`dshmarket/lib/themes.js:53 ownsLoaderEntry`）：entry `name` 等于包名或以 `包名/` 开头 → 否则看 entry id 是否在包 patch 的 `insert` id 集合里。官方插件页则完全不看 entry name，只看依赖 + bundles。
→ `insert.id` 叫什么不影响识别，但 **`insert.name` 必须是包名**（否则 Host 解析不到模块、客户端身份也对不上）。建议统一 `id = name = dsh-supergroup`，为可读，不是机制要求。

### C5（修正）幂等守卫的写法要换
cordis 没有「另一个同名 entry」的句柄，草案的「跳过同名实例」不可实现。而重名风险是两头：
- 小：`@deepseek-ai/dsh-tools/lib/index.js:433` 的 `register` 落在全局层，重名直接抛 `tool "ms2_…" is already registered` → 第二实例 fail。
- 大：`apply` 抛出**之前** `ready` 的异步初始化已启动（`src/plugin2.mjs:169` 起），被 fail 的实例仍可能跑完 `recover()`/`reconcileTasks()`，**往账本写重复事件**。
→ 正确做法：在 apply 最前面抢一把跨进程锁（`$DSH_HOME/supergroup/.instance.lock`，与数据目录解耦，这样「file:// 实例 + 包实例」也能挡）；抢不到就置 `state.error`、**不启动 ready、不注册工具**。锁内容 `{pid, at}`，陈旧判定 = `at < 本进程启动时刻` 或 pid 已死（重启后 pid 复用也不误判）。释放用 `ctx.effect(() => () => release())`（effect 返回值即 disposer）。测试要能 `config.instanceLock:false` 关掉。

### C6（补充）迁移删 insert 时要知道带走了什么
见 C2 末段。

### C7（补充）普通依赖不要顺手加进 bundles
profile `dependencies` 里的 `dsh-connect-trae`、`dsh-pet`、`dsh-tts-bridge` 没有进 `dsh.profile.bundles`，所以侧栏插件页也不显示它们。这是官方设计（未选中的普通依赖不列出），别顺手加。

### C8（**推翻上一版结论**）冷拷贝是必做，不是可选
上一版写「不改数据、不复制也必须成功」——错的。装成包后 `import.meta.url` 推出的 `../data` 是**包目录旁边**（`<profile>/node_modules/dsh-supergroup/../data` 或软链指向的 `<你的工作区>\dsh-supergroup\data`），两者都不等于 `<你的工作区>\dsh_multisession_stage23\data`。legacy 回退只对「从开发目录以 file:// 跑」的场景有效。
→ 结论：**迁移必须冷拷贝**；legacy 回退保留，作用是「防止把数据写进 node_modules」和「开发目录实例不炸」，不是迁移手段。

## 8. 迁移方案（现有实例 → 包安装）

**目标**：`insert id dsh-big-fat-fish`（`file:///<你的工作区>/dsh_multisession_stage23/src/plugin2.mjs`，数据在开发目录 `data\`）→ 包 `dsh-supergroup`（数据在 `%DSH_HOME%\supergroup\`）。

**无损关键**：数据是拷贝不是移动；旧目录全程只读；拷贝前后哈希对账。

**顺序（不可颠倒）**：
1. 退 DSH（CLI 会拒绝运行中的 desktop profile，错误文案「fully quit it」）。
2. 冷拷贝 + 哈希校验（W6.1）。
3. `dsh plugin add`（W6.2）——它只写依赖；bundles 必须手工补或走 GUI。
   > desktop profile 的 `dsh --profile desktop --dump-config` 会被 `rejectElectronProfile` 硬拦；需要 dry-run 时，把 profile 复制到临时 `$DSH_HOME`、目录改名为 `desk-dry` 再跑 `dump-config`，或只做静态校验（`package.json` / `cordis.patch.yml` 正则断言）。
4. 删 insert（必须在启动前；否则两条 entry 并存，第二条会 fail，且它的异步 init 可能写重复账本）。
5. 启动 → 验收。

**不采用「profile config 覆盖旧路径」**：会让 profile 永久携带本机绝对路径，换机即坏，也和文档说的「装完就能用」矛盾。若用户坚持只留一份数据，再用覆盖行（`- id: dsh-supergroup / name: dsh-supergroup / config: {…}`，与 image-gen 那条同形状），并在 README 标注为手工定制。
